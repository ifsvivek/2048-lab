# ADR 0005 — MCP server as a thin, stateless layer

**Status:** accepted

## Decision
* A separate Worker (`apps/mcp`, Hono + official MCP SDK, Streamable HTTP)
  builds a fresh `McpServer` per request (stateless mode: no session IDs), so
  any isolate serves any request and nothing is stored there.
* It calls the API through a **service binding** — no game logic, validation or
  persistence is duplicated; errors are the API's `{error, code, message}`
  objects returned with `isError: true` (INVALID_MOVE carries the state).
* Tool results carry `structuredContent` + an `outputSchema` for game-state
  tools, trimmed to decision-relevant fields.
* **Versioning**: tool names and required inputs are stable within v1; new
  tools and optional fields are additive; breaking changes ship on `/v2/mcp`.
